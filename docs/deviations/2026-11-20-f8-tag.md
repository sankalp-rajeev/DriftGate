# F8 release-tag selection, 20 November 2026

The original runner used GitHub's `releases/latest` endpoint as a proxy for the
latest build tag. This prioritized the stable release channel and returned
`v1.0.0` (`b1b770d90`, 13 November). Release names and channels do not order the
numbered build tags by creation time. The selected commit was four calendar days
older than the 17 November baseline pin (`8c16babba`), so the runs exercised a
downgrade.

The corrected selector filters to exact `b[0-9]+` tags and orders them by Git's
creator date. That is the tagger timestamp for annotated tags and the tagged
commit's committer timestamp for lightweight tags. It uses the first timing
start in the study log on resumed studies. For this repair the stated cutoff was
19 November 2026 at 21:29 EST (20 November at 02:29 UTC). The newest eligible tag
was [`b12557`](https://github.com/ggml-org/llama.cpp/releases/tag/b12557), created
19 November at 17:21:24 EST (22:21:24 UTC), pointing to
`b94959a64d011915d77a5381c7d4846dcda99530`. The repair records the tag, full
commit, date and cutoff in the study's `f8.json`.

The original files are preserved under
`runs/2026-11-19-study/faults/F8-downgrade-v1.0.0/`, including the original
`f8.json` and run logs. Both corrected repetitions use the study's original L3
budget, measurement seed 0 and run seeds 1 and 2. Each run records the
`llama-server --version` output and checks the live server build against both
the selected commit and the baseline's recorded build. The matrix uses the
corrected repetitions and the existing calibration files.

**No threshold changed.** The frozen pre-registration and original reference,
calibration and other fault results are preserved.
