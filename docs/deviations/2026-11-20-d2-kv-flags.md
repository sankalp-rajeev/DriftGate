# D2 coverage of F3, 20 November 2026

The study review found that [D2's `llama-perplexity` invocation](../../gate/d2.py) omits
the F3 flags `--cache-type-k q4_0 --cache-type-v q4_0 --flash-attn on`. F3 applies those
flags to llama-server while keeping the Q8_0 weights. D2 evaluated the Q8_0 weights with
llama-perplexity's default cache settings. Its recorded mean KL of 0 and matrix cell of
0/2 are valid weight comparisons but do not measure the KV-cache fault. The same caveat
applies to the KL coordinate of the original F3 point in RQ2. The live F3 D5 accuracy drop
of 57.8125 percentage points was measured with the fault active.

D2 stays weights-only in the gate by design. It can detect artifact drift and does not
test the effect of candidate serving KV-cache settings. The results report retains the
pre-registered seven-point calculation and flags the original F3 point. The exploratory
rank correlation uses the six weight quantizations.

One exploratory F3 run used the same pinned llama.cpp build, Q8_0 weights, reference
logits, 512-token context and two threads, with all three F3 flags passed explicitly.
Mean KL was **5.337437**, p99 KL was **14.053483**, and the same-top-token rate was
**4.804%**. This single run measures the combined effect of the F3 cache and flash-attention
settings in llama-perplexity. The result stands separately from both correlations and the
gating matrix. The [run record](../results/f3-kv.json) gives the exact command and artifact hashes.

The frozen pre-registration, original outputs, and thresholds are preserved. The front
matter carries the approved fault and baseline pins for the study runner.
